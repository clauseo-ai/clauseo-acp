# Every #[expect(..)] and #![expect(..)] in the repo's Rust files, one line per site and lint.
# The expect-allowlist static check (xtask/src/checks/expect_allowlist.rs) fails on a site with no
# line here and on a line with no site. The code owner approves each line (CODEOWNERS: /xtask/).
#
# Format: <path> <item> <lint>, separated by spaces. `#` starts a comment; blank lines are skipped.
# - <path>: the file, relative to the repo root, with `/`.
# - <lint>: as the attribute writes it, without spaces (`clippy::unwrap_used`). One attribute that
#   names several lints needs one line per lint; `reason = ".."` is not a lint.
# - <item>: the item the attribute sits on, as a path from the top of the file joined with `::`:
#   `timed` for a function, `Entry::replacement` for a field, `Printer::put` for a method (an impl
#   is named by the last segment of its type, without generics), `Trait::method` for a trait's
#   default method, `m::f` inside a module, `E::V` for a variant, `S::0` for a tuple field. An
#   attribute on a statement, an expression, a parameter or a generic names the nearest item
#   around it, and so does one inside a macro body. At the top level of a file, an attribute on no
#   named item (an inner attribute of the file, a `use`, an `extern` block, a macro call) is `-`.
# Sites under cfg_attr and inside macro bodies count too. N identical sites need N identical
# lines. The order of the lines is not checked; keep them grouped by file.
# `allow` and `warn` are never listed: the check fails each of them in every form, and so does
# an attribute in a macro body whose name or lint is a metavariable, a `#` there with no brackets
# after it, and a #[path] or include! of a file the check does not read.
