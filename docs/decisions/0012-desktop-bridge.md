# 0012: The desktop bridge's commands, capability and stream format

## Context

[0001](0001-rust-webview-boundary.md) puts the security boundary in Rust and asks for a new
record for each command, each capability and each change to the patch protocol. The window now
reaches the session host (`clauseo-host`): it runs commands, reads views, follows streams,
answers permissions and picks folders. Script in the page may be an attacker's
([threat model](../threat-model.md), "Webview"), so the surface stays narrow and every argument
is checked in Rust. Tauri 2.12.4 hands a channel message to the page with one `eval` only when its
JSON is shorter than 8192 bytes (`MAX_JSON_DIRECT_EXECUTE_THRESHOLD`, `tauri/src/ipc/channel.rs`);
a longer one costs a second fetch round trip.

## Decision

**Commands.** Nine `async` commands in `crates/desktop/src/commands.rs`. Each returns
`Result<T, HostError>`, and each host call runs as `Principal::LocalDesktop`, which the bridge
supplies; the webview never names a principal. Tauri decodes the arguments into protocol's types,
which check ids and bounded values as they decode; the bridge then checks what decoding cannot.

| Command | Arguments | Answer | Rust checks |
|---|---|---|---|
| `dispatch` | `command: CommandEnvelope` | `CommandOutcome` | `CommandEnvelope::validate`; refuses `AnswerPermission` and a `CreateMatter` whose folder ref this run's `pick_folder` did not issue (`command.invalid`) |
| `query` | `query: HostQuery` | `QueryResult` | decoding (`PageLimit`, `ReadLen` bounds) |
| `open_stream` | `channel: Channel<StreamMessage>` | `()` | one channel per window; a second call replaces it and drops its subscriptions |
| `subscribe` | `stream: StreamId, after: ViewPosition \| null` | `()` | needs `open_stream` first |
| `unsubscribe` | `stream: StreamId` | `()` | needs `open_stream` first |
| `ack` | `stream, epoch: ViewEpoch, cursor: Cursor, frames: u32` | `()` | `frames` at most what the window was sent |
| `answer_permission` | `thread: ThreadId, request: PermissionRequestId, option: AgentChoiceId` | `()` | the request is pending and offered `option`; an `allow_always` option first opens a native confirm drawn by Rust, and declined there the call fails with `transport.unauthorized` |
| `pick_folder` | none | `FolderRefId \| null` | the native folder dialog drawn by Rust, then `register_folder`; `CreateMatter` refuses a refused folder with `matter.folder_refused` |
| `display_info` | none | `{ platform: "mac" \| "windows" \| "linux" }` | none |

The confirm shows fixed text: nothing the agent wrote reaches it. A Tauri rejection (an argument
that does not decode, a command no capability grants) reaches the page as a plain string; the
webview's transport maps it to `{ code: "internal", message, retryable: false }`.

**Capability.** `build.rs`'s `AppManifest` lists the nine commands, so tauri-build writes an
`allow-<command>` permission for each into `permissions/autogenerated/`. `capabilities/main.json`
grants exactly those nine to the `main` window and nothing else; the dialog plugin stays Rust-only.
A test checks the command list in `commands.rs`, `lib.rs`'s handler, `build.rs`, the capability
and the TypeScript bindings agree.

**Stream format.** One `ipc::Channel` per window. Each message is either an `EncodedEvent::json()`
text sent as it is (`InvokeResponseBody::Json`, never parsed or encoded again) when it is shorter
than 8192 bytes, or a fragment of a longer one:
`{"fragment":{"id":<u32, per window, increasing>,"index":<u16 from 0>,"count":<u16>,"text":"<piece>"}}`.
The pieces' texts joined in index order are the event's text exactly; the transport joins them and
parses once. Every message, fragments included, is shorter than 8192 bytes.

**Backpressure.** The bridge counts bytes by message: the webview acks with `frames`, the number of
channel messages it has received and processed since `open_stream` (a fragment counts one). Past
256 KB unacknowledged the window pauses: its host subscriptions are dropped, and once acks bring
the count to 0 each stream is subscribed again after its last acknowledged `(epoch, cursor)` (or
from a `Reset` with none). 5 s with bytes unacknowledged and no ack progress restarts every stream
the same way at once, paused or not, so a lost ack cannot stall a window. The host answers a
restart with the tail or a `Reset`; the webview applies only the next cursor, so replays are no-ops.
The logic is a sans-IO state machine (`bridge/window.rs`) that takes time as an argument.

**Bindings.** `ui/app/src/transport/bindings.ts` is written by tauri-specta from a unit test
(`src/commands/bindings.rs`) that fails when the file on disk changed. tauri-specta, specta and
protocol's `specta` feature are dev-dependencies only: the app registers the commands with
`tauri::generate_handler!` and carries no specta code. Protocol's types go in through `WireFormat`,
and the test checks each exports exactly as protocol's own `WireFormat` export.

**Decided here** (from the R12 brief):

- Past the cap, the bridge drops its subscription and resubscribes after the last acknowledged
  cursor once acks catch up. Reason: one recovery path (synthesis 2.6).
- `EncodedEvent` text goes out as is, never re-encoded (R11 "Encode once"); a patch over 8 KB goes
  as numbered fragments the transport joins before parsing.
- The `e2e` build reads `E2E_MATTER_DIR` instead of opening the folder dialog; never in release
  builds (the rule in `crates/desktop/src/e2e.rs`).

The `e2e` build likewise answers the "always allow" confirm from `E2E_CONFIRM_ALWAYS` (`accept` or
`decline`) instead of drawing it, since a native dialog cannot be clicked over CDP; never in
release builds. With either variable unset, the dialog is drawn.

## Consequences

- The page reaches nine typed commands and no plugin; a tenth command needs a new record, a
  permission and a line in each list the test compares.
- A large patch costs a few fragment messages instead of one fetch round trip.
- A window that falls 256 KB behind stops receiving until it catches up, then gets the tail or a
  `Reset`; the host keeps no per-window queue.
- Whether a folder may be a matter stays the host's rule, checked at `CreateMatter`; `pick_folder`
  only registers what the lawyer picked.
- A change to the message format, the cap or the watchdog is a change to the patch protocol and
  needs a new record.
