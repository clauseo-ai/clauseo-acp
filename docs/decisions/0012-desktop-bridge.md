# 0012: The desktop bridge's commands, capability and stream format

## Context

[0001](0001-rust-webview-boundary.md) puts the security boundary in Rust and asks for a new
record for each command, each capability and each change to the patch protocol. The window now
reaches the session host (`clauseo-host`): it runs commands, reads views, follows streams,
answers permissions and picks folders. Script in the page may be an attacker's
([threat model](../threat-model.md), "Webview"), so the surface stays narrow and every argument
is checked in Rust. Tauri 2.12.4 hands a channel message to the page with one `eval` only when its
JSON is shorter than 8192 bytes (`MAX_JSON_DIRECT_EXECUTE_THRESHOLD`, `tauri/src/ipc/channel.rs`);
a longer one costs a second fetch round trip.

## Decision

**Commands.** Nine `async` commands in `crates/desktop/src/commands.rs`. Each returns
`Result<T, HostError>`, and each host call runs as `Principal::LocalDesktop`, which the bridge
supplies; the webview never names a principal. Tauri decodes the arguments into protocol's types,
which check ids and bounded values as they decode; the bridge then checks what decoding cannot.

| Command | Arguments | Answer | Rust checks |
|---|---|---|---|
| `dispatch` | `command: CommandEnvelope` | `CommandOutcome` | `CommandEnvelope::validate`; refuses `AnswerPermission`, `SetMode`, `SetConfigOption`, and a `CreateMatter` whose folder ref this run's `pick_folder` did not issue (`command.invalid`) |
| `query` | `query: HostQuery` | `QueryResult` | decoding (`PageLimit`, `ReadLen` bounds) |
| `open_stream` | `channel: Channel<StreamMessage>` | `()` | one channel per window; a second call replaces it and drops its subscriptions |
| `subscribe` | `stream: StreamId, after: ViewPosition \| null` | `()` | needs `open_stream` first |
| `unsubscribe` | `stream: StreamId` | `()` | needs `open_stream` first |
| `ack` | `positions: Ack[], messages: u32` | `()` | `messages` at most what the window was sent; no stream named twice (both refused whole, `command.invalid`); a position of a stream the window does not follow is dropped |
| `answer_permission` | `thread: ThreadId, request: PermissionRequestId, option: AgentChoiceId` | `()` | the request is pending and offered `option`; the plan-exit mode options are refused (`command.invalid`, below); an `allow_always` option first opens a native confirm drawn by Rust, and declined there the call fails with `transport.unauthorized`; only `allow_once`, `reject_once` and `reject_always` skip it, and a kind this version does not know is refused (`command.invalid`) |
| `pick_folder` | none | `FolderRefId \| null` | the native folder dialog drawn by Rust, then `register_folder`; `CreateMatter` refuses a refused folder with `matter.folder_refused` |
| `display_info` | none | `{ platform: "mac" \| "windows" \| "linux" }` | none |

The confirm shows fixed text: nothing the agent wrote reaches it. `SetMode` and
`SetConfigOption` are refused because a mode can widen what the agent does without asking
(Claude's `bypassPermissions`), an escalation 0001 puts behind a native dialog drawn by Rust; the
internal window never sends them. For the same reason `answer_permission` refuses the four
option ids claude-agent-acp 0.89.1 offers on leaving plan mode that switch the session's mode:
`exit-plan-bypass` and `exit-plan-clear-bypass` (`allow_always`, to `bypassPermissions`), and
`exit-plan-auto` and `exit-plan-clear-auto` (auto mode). Follow-ups: a mode command that
classifies the mode and draws that confirm first; and acp sending
`allowDangerouslySkipPermissions: false` in its session meta, so the bypass options are never
offered. A Tauri rejection (an argument
that does not decode, a command no capability grants) reaches the page as a plain string; the
webview's transport maps it to `{ code: "internal", message, retryable: false }`.

**Capability.** `build.rs`'s `AppManifest` lists the nine commands, so tauri-build writes an
`allow-<command>` permission for each into `permissions/autogenerated/`. `capabilities/main.json`
grants exactly those nine to the `main` window and nothing else; the dialog plugin stays Rust-only.
A test checks the command list in `commands.rs`, `lib.rs`'s handler, `build.rs`, the capability
and the TypeScript bindings agree.

**Stream format.** One `ipc::Channel` per window. Each message is either an `EncodedEvent::json()`
text sent as it is (`InvokeResponseBody::Json`, never parsed or encoded again) when it is shorter
than 8192 bytes, or a fragment of a longer one:
`{"fragment":{"id":<u32, per window, increasing>,"index":<u16 from 0>,"count":<u16>,"text":"<piece>"}}`.
The pieces' texts joined in index order are the event's text exactly; the transport joins them and
parses once. A third kind tells the webview a stream the bridge restarted (after a pause or a
watchdog fire) failed to subscribe: `{"stream_failed":{"stream":<StreamId>,"error":<HostError>}}`;
the stream stays followed and the bridge's clock tries it again 5 s later, the wait doubling with
each failure up to 60 s, until a try succeeds or the webview subscribes or unsubscribes it. A
`subscribe` the host refuses returns the error and follows nothing. Every message is shorter than
8192 bytes. The reader tells the kinds apart by the top-level key: `fragment`, `stream_failed` and
`timed` (below) are reserved, and no `HostEvent` kind may take one (a desktop test serialises one
value of every `HostEvent` variant and checks).

**Timed events (`e2e` builds only).** For the speed scoreboard, the `e2e` build (and `marks`,
which includes it) sends an event whose text fits one message with the wrapper as
`{"timed":{"received_ms":<f64>,"event":<the event's text>}}`: `received_ms` is when the bridge
took the event from the host subscription, in ms since the Unix epoch, and the event's text goes
in as it is, between a fixed prefix and suffix. A longer event goes as above, with no time. A
timed message counts as one message of its wrapped length for acks and the cap. The default build
never sends one. The same builds add, each in its own capability file that `tauri.conf.json` does
not name (`capabilities/e2e.json`, `capabilities/marks.json`; with the feature, setup adds them with
`add_capability`, since the checks refuse every way to name them in the config): `perf_channel_bytes` (`e2e`, the bytes sent down every
channel since start) and `marks_memory` and `marks_finish` (`marks`, `crates/desktop/src/marks.rs`).
The default build's commands, permissions and capability are as listed above.

**Backpressure.** The bridge counts bytes by message: the webview acks with `messages`, the number
of channel messages it has received and processed since `open_stream` (a fragment and a
`stream_failed` count one each), and with the positions it has applied, at most one per stream and
maybe none, so one `ack` call per flush carries both. Each position goes to `HostHandle::ack` and
becomes its stream's restart point. Past
256 KB unacknowledged the window pauses: its host subscriptions are dropped, and once acks bring
the count to 0 each stream is subscribed again after its last acknowledged `(epoch, cursor)` (or
from a `Reset` with none). 5 s with bytes unacknowledged and no ack progress restarts every stream
the same way at once, paused or not, so a lost ack cannot stall a window. The watchdog fires once
per stall: it fires again only once acks cover every message sent before it fired. A page that
stops acking so gets one event more after the fire, never one every 5 s: its unacknowledged bytes
stay at most the larger of 256 KB and what was unacknowledged at the fire, plus one event. The host answers a
restart with the tail or a `Reset`; the webview applies only the next cursor, so replays are no-ops.
The logic is a sans-IO state machine (`bridge/window.rs`) that takes time as an argument.

**Bindings.** `ui/app/src/transport/bindings.ts` is written by tauri-specta from a unit test
(`src/commands/bindings.rs`) that fails when the file on disk changed. tauri-specta, specta and
protocol's `specta` feature are dev-dependencies only: the app registers the commands with
`tauri::generate_handler!` and carries no specta code. Protocol's types go in through `WireFormat`,
and the test checks each exports exactly as protocol's own `WireFormat` export.

**Decided here** (from the R12 brief):

- Past the cap, the bridge drops its subscription and resubscribes after the last acknowledged
  cursor once acks catch up. Reason: one recovery path (synthesis 2.6).
- `EncodedEvent` text goes out as is, never re-encoded (R11 "Encode once"); a patch over 8 KB goes
  as numbered fragments the transport joins before parsing.
- The `e2e` build reads `E2E_MATTER_DIR` instead of opening the folder dialog; never in release
  builds (the rule in `crates/desktop/src/e2e.rs`).

The `e2e` build likewise answers the "always allow" confirm from `E2E_CONFIRM_ALWAYS` (`accept` or
`decline`) instead of drawing it, since a native dialog cannot be clicked over CDP; never in
release builds. With either variable unset, the dialog is drawn.

At exit the `e2e` build calls `std::process::exit` once the host thread has joined, instead of
`app.exit`. On Windows in a session with no visible window (CI), tao's loop never delivers
`RunEvent::Exit`, so `app.exit` would leave the process running. A side effect: window-state never
saves in this build, so e2e runs do not write the real app config folder.

## Consequences

- In the default build the page reaches nine typed commands and no plugin; a tenth command needs a new record, a
  permission and a line in each list the test compares.
- A large patch costs a few fragment messages instead of one fetch round trip.
- A window that falls 256 KB behind stops receiving until it catches up, then gets the tail or a
  `Reset`; the host keeps no per-window queue.
- Whether a folder may be a matter stays the host's rule, checked at `CreateMatter`; `pick_folder`
  only registers what the lawyer picked.
- A change to the message format, the cap or the watchdog is a change to the patch protocol and
  needs a new record (or, while this one is proposed, an amendment here, as `timed` was).
- A window whose page stops acking holds a bounded amount unacknowledged, not one event more
  every 5 s. The cost: when the ack that follows a watchdog fire is lost as well, the window waits
  for its next ack (the next event it is sent) instead of a second fire.
